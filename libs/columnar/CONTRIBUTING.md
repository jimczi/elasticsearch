# Contributing to `libs/columnar/`

Several people may work on this library concurrently — possibly with agent-assisted loops.
The library has a stable public API and a single segment-wide format version; respecting
those two contracts is how unrelated changes stay safe to compose.

## Stable contracts

These are the surfaces other code depends on. Changing them needs coordinated work, not
an isolated PR:

- **`ColumNARDocValuesFormat` constructor and SPI name.** The format is per-field, with
  arguments persisted on disk by name. Adding a parameter is a breaking change.
- **The four SPI interfaces** (`NumericBlockEncoder`, `BytesBlockEncoder`,
  `BlockEncoding`, `SkipIndex`). New interface methods break every downstream
  implementation.
- **Persisted names of built-in implementations.** The string a writer puts on disk is
  the read-side lookup key, forever.
- **Bridge `Field` and `Values` types** (`ColumNARLongField`, `PackedLongsFromBinaryDocValues`,
  …). External indexing and reading code references them by name; signatures stay stable.

## Routine improvements — open to anyone

These changes fit in a single PR and don't need cross-team sync:

- **New encoder / encoding / skip-index implementation.** Pick a fresh `String getName()`,
  add the SPI service file, extend the corresponding `Base*TestCase` for conformance.
- **Faster / smaller bytes inside an existing encoder.** Bump
  `ColumNARDocValuesFormat.VERSION_CURRENT` once for the whole library and branch on
  `formatVersion` inside your `decode`. Old segments stay readable forever.
- **New workloads in the storage report.** Add them to `StorageReportTests`; the report
  re-renders the table.
- **Bug fixes that preserve on-disk bytes.** No version bump needed.
- **Test improvements.** Standard battery in `Base*TestCase`; per-impl tests in the
  matching `*Tests` class.

## Larger changes — discuss first

- New field type on disk (new `FIELD_TYPE_*` byte).
- Removing an existing encoder / encoding / skip-index name from the registry (this is
  an intentional BWC break — old segments stop loading).
- Changing the bridge's payload format (the `'L'` / `'B'` shape markers, or how counts
  and values pack together).
- Refactoring the per-field metadata layout.

These touch every reader and every old segment. Sync on intent before writing the code.
A short design issue + a draft PR with the wire-format diff is enough.

## Agent / loop hygiene

When iterating with an agent on this library, the contract above is what stays stable
between runs. Constructor changes, registry shape, SPI surface — those should not
spontaneously shift on every loop. Small isolated improvements (a faster bit-pack inner
loop, a new encoder, a doc fix) are safe. Whole-format refactors aren't.

If you find yourself rewriting more than a couple files outside the one you're improving,
that's a signal to pause and align — either the contract needs to evolve (deliberate),
or the local change shouldn't be reaching that far (revert).

## Reporting

`docs/REPORTS.md` is the running storage snapshot. It's regenerated by `StorageReportTests`
and captures the full matrix — single- and multi-valued, numeric and bytes, at sizes large
enough to cross multiple blocks. The report file is meant to be regenerated periodically
(e.g. nightly CI) so maintainers can spot regressions and pick follow-ups from the data.
**Don't list future work in the report** — it's a snapshot of current state. Open issues
for follow-up items instead, and link them from your PR.

## Docs stay in sync with code

`README.md`, `docs/ENCODERS.md`, `docs/CONFIGURING.md`, `docs/BENCHMARKS.md` describe the
library *as it is*. Any code change that affects names, wire format, or contracts must
update these in the same PR. Granular per-class wire-format details live on the Javadoc
of each implementation and in each package's `package-info.java`.
